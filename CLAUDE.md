# YARC — notes for Claude sessions

Open-source Arc-browser replacement (Electron 45 / Chromium 156, React 19, TypeScript 7, electron-vite 6). Arc shuts down 2026-12-22; the goal is a browser that feels familiar to Arc users, with **macOS as the main platform** (most Arc users), Windows second.

## Commands

- `pnpm install` (postinstall downloads the Electron binary) · `pnpm dev` · `pnpm build`
- `pnpm typecheck` · `pnpm test` (unit, `node --test`) · `pnpm test:e2e` (builds, then Playwright drives the real app)
- Icons: edit `build/icon.svg` (and `icon-small.svg` for 16–32px), then `pnpm exec electron scripts/render-icons.mjs` and commit the PNG/ICO it writes.
- What's New boards: `pnpm build`, `node scripts/board-preview.mjs <spotlight id> [--save-sizes] [--wait=<ms>]` draws one in the real app and prints where its picture is (`--wait=9300` for the end of a picture's loop).
- README GIFs and screenshots: `pnpm build`, `node scripts/readme-media/record.mjs`, `python3 scripts/readme-media/make.py` (docs/development.md).
- `pnpm dist:mac` / `dist:win` → installers in `release/`. Releases are automatic and daily (since 2026-11-21, after 24 releases in two days): at 04:17 UTC `main` gets the next semver tag if a PR merged since the last one changes the app (the biggest bump they ask for: patch, or PR labels `release:minor` / `release:major`; `release:skip` PRs and ones that only touch `.github/`, `docs/`, `test/` or top-level Markdown don't count). PR label `release:now` releases at merge (urgent fixes; Dependabot puts it on Electron bumps). CI builds it and publishes once all platforms pass. The version comes from the tag (`package.json` is `0.0.0-dev`).
- Every PR description needs a `## What's New` section (`.github/pull_request_template.md`, checked by `whats-new.yml`): what What's New and the update card show of it (`scripts/changelog.mjs`); the title is only for GitHub. Keep it short, release notes are read in seconds:
  - Usually **one line for the whole PR**: a sentence in words for users that says what they can now do, or what no longer goes wrong.
  - Not a list of everything the PR changed. One feature is one line: its buttons, menus, shortcuts and edge cases go in the description above the section, not in it. Small fixes and polish that came along with the feature aren't listed, and neither is a fix for something that was never released.
  - More lines only when the PR really ships separate things a user would each notice: two big features, or a feature and an unrelated fix. Three lines is already a lot; past that, ask whether each line would be missed.
  - `none` for what they won't notice (CI, tests, docs, refactors, logging).
  - No "like Arc", no PR numbers, no internals (file, function or setting names users never see).
  - Example, for a PR that adds pinning of extensions with a popover, a context-menu item and a menu-position fix: `Pin the extensions you use to the address field; the puzzle button lists the rest.` That one line, not three.
- A big feature also gets a spotlight card in What's New, shown once per profile: an entry in `src/shared/spotlights.ts` and its picture in `src/renderer/src/panels/spotlight-pictures.tsx`, in the feature's own PR. When the feature has something to show or try, it also gets a What's New board, the canvas its What's New card offers with a Try It on a Canvas button (the card opens by itself at launch when an unseen spotlight waits; the board never does): `src/main/features/boards/<spotlight id>.json`, listed in `src/main/features/whats-new-boards.ts`. Make it as `docs/whats-new-canvas.md` ("Making a board") says, look at it with `node scripts/board-preview.mjs <spotlight id>`, and put that picture in the PR.

## Architecture (`docs/architecture.md`: diagrams, where to change what)

- `src/main` is in tiers. **Sensitive** (the security gate rates them high, `CODEOWNERS` covers them): `core/` (views, windows, sessions, permissions, IPC guards, page scripts, state and history files; imports only `core/` and `shared/`), `net/` (ad blocking, extensions, `outbound.ts`: every request a feature makes), `update/`, `sync/`, `importers/`, `index.ts`, `ipc.ts`. **Open**: `features/` and `browser.ts`, which use no privilege themselves (no `ipcMain`, `webPreferences`, `executeJavaScript`, `fetch(`, sessions, cookies, `child_process`…): they call one narrow function in a sensitive tier, or add one. `test/unit/architecture.test.ts` checks all of it and says where code belongs; move the code, don't add an exception.
- The two ways into main each have one file: `src/main/ipc.ts` is everything the UI can ask (`handleUi`/`onUi`, channels in `IPC`); a web page's channels are `PAGE_IPC` (`src/shared/ipc.ts`), registered through `core/page-ipc.ts`.
- Main process owns all state: `src/main/browser.ts` (controller), persisted in `state.json` via `src/main/core/store.ts`. Renderers get full snapshots and send typed `Action`s (`src/shared/actions.ts`).
- Window = UI webContents (sidebar) under per-tab `WebContentsView`s, plus a transparent overlay view on top for the command bar/panels (`src/main/core/window.ts`).
- Several main windows (⌘N) share one `Browser` and its state. Per window (`WindowView` in `state.windows`, restored at launch): space, selected tab per space, splits, sidebar visibility, bounds. The state's `activeSpaceId`/`activeItemId`/`splits`/`sidebarVisible` are always the *current* window's; `use(win)` swaps them (`src/main/features/window-state.ts`). A tab's view sits in one window; another window selecting it shows a still. Design: `docs/multi-window.md`.
- One session partition per profile (`persist:profile-<id>`): extensions (`extensions.ts`), ad blocking (`adblock.ts`), history (`history.ts`, `node:sqlite`). Spaces map to profiles; favorites belong to profiles.
- Incognito windows (⇧⌘N, Dock, File menu, link context menu) are a second `Browser` per window, constructed with `main`: in-memory `Store` and `History`, non-persistent `incognito-<id>` partitions, no extensions, the main ad blocker and updater; disposed when the window closes. IPC is registered once and routed to the controller that owns `e.sender`.
- YARC's own pages are served from `yarc://ui/` (`src/main/core/ui-origin.ts`), sandboxed, and can't navigate away. The preload only exposes `window.arc` on that origin, and every UI IPC handler (`handleUi`) refuses other senders. Never load a web page into a UI view or give one the `ui.js` preload.
- History sync (`src/main/sync/`, `docs/history-sync.md`): encrypted per-device logs in a folder the user already syncs (iCloud Drive…), a cloud drive YARC signs in to (Google Drive, OneDrive, Dropbox: app folders only, through a local copy kept in step by `remote.ts`), a WebDAV server, or between computers on the same network; no YARC server. The cloud drives need YARC's client IDs in `cloud-drives.ts`. Only the main controller has a `HistorySync`, so incognito never syncs. The derived key uses `safeStorage` on Windows/Linux but not macOS (keychain prompt per update).
- Shortcuts are matched in `before-input-event` on every webContents (`src/shared/keymap.ts`, physical key codes). Playwright's synthetic keys bypass this — e2e tests use `wc.sendInputEvent`.
- Research notes in `docs/`: Arc behavior & shortcuts (`arc-reference.md`), Arc's `StorableSidebar.json` format (`arc-data-format.md`), Electron/Google sign-in/packaging gotchas (`electron-notes.md`).

## Code rules

- Fewest lines that stay readable.
- Names say what a thing is or does: no one-letter names (`s`, `t`, `w`, `e`, `r`…), parameters and callback arguments included; `_` prefix only for an unused parameter.
- A comment that seems necessary means a name is wrong: rename, or extract a function whose name says it. The only comments are a one-line *why* that comes from outside the code (an Electron/Chromium/OS/website behaviour, a security or ordering reason).
- A file over 500 lines is a smell: check that it hasn't taken on more than one job.
- Keep the main process cheap: high-frequency sources (blocked requests, download progress) use `emitSlowly()`, not `emitSoon()`; data only a panel shows (archive, site permissions) reaches the overlay only while that panel is open (`withPanelData`); UI webContents are created on first use, and a child view's webContents is closed with its window (Electron doesn't).
- The theme is the tokens in `src/renderer/src/tokens.css` (`docs/design.md`):
  - Colour, radius, type size, motion and shadow come from a token, never a literal.
  - None fits: reuse the nearest; a really new value becomes a token there and a line in `docs/design.md`.
  - `test/unit/design-tokens.test.ts` fails on a hex colour; don't add exceptions to it.
  - Own values only in `panels/spotlights.css` and for what is drawn on a canvas (`canvas.css`).
- Unit tests run under `node --experimental-strip-types`: no parameter properties, enums or namespaces in anything they import.
- e2e tests reach `Browser` untyped (`globalThis.arcBrowser`), so after renaming a member grep `test/`. Wait for the page's DOM to show a change before measuring it; main's state alone races.

## Decisions already made (don't re-litigate)

- Renamed from Arc Shell to YARC on 2026-11-02. Kept on purpose: the `appId` `org.arcshell.browser`, the Windows registry keys and ProgIDs (`ArcShell*`), and an existing `Arc Shell` profile folder (`src/main/core/profile-dir.ts`). Cookies aren't encrypted (Electron's cookie-encryption fuse is off), so no Keychain key is tied to the old name. The repo moved from `yenebeb/arc-shell` to `yenebeb/yarc` the same day; GitHub redirects the old name (older installed apps poll it for updates), so never create a new repo called `arc-shell` on that account.
- Google sign-in needs Electron's own UA (only the app-name token stripped); a spoofed Chrome UA is rejected. Chrome Sync is impossible for non-Chrome browsers → import instead.
- Built-in ad blocking (Ghostery engine) because Electron has no `declarativeNetRequest`. Uses a custom adapter, not `enableBlockingInSession` (global IPC handlers break with multiple sessions). The lists come from uBlock Origin's own site, not Ghostery's copies (`src/main/net/adblock-build.ts`): those lagged three months and YouTube restarted videos on ads (2026-11-22). Scriptlets run from a preload before the page's own scripts.
- No Apple Developer ID: macOS releases are signed with one self-signed certificate from CI (`MAC_CODESIGN_P12` / `MAC_CODESIGN_P12_PASSWORD` secrets, `scripts/mac-sign.mjs`), so camera/microphone permissions survive updates; ad-hoc (`identity: "-"`) without the secret. Not notarized, so Gatekeeper still needs *Open Anyway*. Never replace the certificate: every Mac would be asked for permissions again (`docs/electron-notes.md` section 9).
- Cookie encryption (Electron's `EnableCookieEncryption` fuse, `scripts/after-pack.mjs`) is on for Windows and Linux only. On macOS, without an Apple team ID, the keychain partition is the cdhash, so every update would ask for the login password; a self-signed certificate doesn't change that (tested, `docs/electron-notes.md` section 8). Once the fuse is on for macOS, never change the app name there: the "<name> Safe Storage" item would change and every cookie would be lost. Windows (DPAPI) is not yet tested on a real machine.
- Hardening (2026-11-19 audit): Electron fuses `RunAsNode`, `NodeOptions`, `NodeCliInspect` and `GrantFileProtocolExtraPrivileges` are off on every platform; app.asar integrity is checked on macOS (`scripts/after-pack.mjs`). macOS builds use the hardened runtime with `build/entitlements.mac.plist`. A packaged build exits on `--remote-debugging-port/pipe`. The Ed25519 update key is only used in release.yml's `sign` job (no dependencies installed, `release-signing` environment); jobs that run dependency code get a read-only token.
- Nothing collected is a headline feature (2026-11-21): no telemetry, usage counts, crash reports or YARC servers. A daily install count shipped and was removed the same day; platform numbers come from GitHub's update downloads (`node scripts/usage.mjs`). Never add a ping.
- Security review pipeline (2026-11-27, `docs/security-review.md`): merging is not publishing. `security-gate.yml` (`pull_request_target`, runs only `main`'s `.github/security/`, reads a pull request as git objects and never checks it out or runs it) classifies risk from the changed files; a contributor's change needs a maintainer's sign-off (label `security-approved`) bound to the commit, and, once `reviewer.enabled` in `policy.json` is turned on (it ships off: no key, no spend, checks by hand), a maintainer-started AI review first (`ready-for-security-review`). The release waits for a maintainer's approval of the `release-signing` environment after a check of every commit and, with the reviewer on, one AI review of the whole release. State (budget of €20/month, reviews, sign-offs, exceptions) is the `security-ledger` branch. It fails closed; the way out is a recorded exception. Never add a step that runs pull request code to those workflows, and never let the AI report open the gate.
- Repository rulesets, with no bypass for anyone: `main` changes only through a PR whose CI passed, `check` and the `e2e` job on Ubuntu and Windows (macOS e2e runs but isn't required since 2026-11-24: its runners often queue for 15 minutes and then give up; no approval needed, no force-push or deletion), with linear history and verified signatures, so PRs are squash-merged (the only merge method the repo allows) and every commit in a PR must be signed: this repo's git config signs with SSH (`commit.gpgsign`, key `~/.ssh/id_ed25519`, registered on GitHub as a signing key); `v*` tags can be created (the release workflow does) but never moved or deleted. A failed release leaves its tag: fix forward with the next merge.

## Status / next steps

Windows: unit + e2e + installed. macOS (2026-11-01, Apple silicon): unit + e2e pass, `dist:mac --dir` packages and launches. Checked on macOS by driving the app through `YARC_TEST` (no real keyboard/trackpad/screen capture available to the agent):

- Import from Arc with real data: spaces in Arc's order, profile names, favorites, pinned tabs and folders, archive and history all import. Arc's named space icons (`customInfo.iconType.icon`, Ionicons names) are mapped to emoji. Gaps: untitled spaces become "Space N"; spaces without a theme get palette colors.
- Shortcuts from a focused page `<input>` via `sendInputEvent`: Cmd+L/D/S/W/, , Ctrl+2, Ctrl+Tab with Ctrl keyup. Cmd+W never closes the window (the Window menu role has no Close item on macOS).
- Traffic lights: hidden with the sidebar, shown during hover-reveal and back after; no gap in native fullscreen. Links from other apps open a Little Window.

Still needs a human on a Mac:

1. Traffic lights' visual alignment with the top bar; window dragging from the sidebar and from the drag strip when the sidebar is hidden.
2. Two-finger horizontal swipe on the sidebar (direction and sensitivity like Arc).
3. Real keystrokes through the native menu: Cmd+C/V/X/A/Z in pages and the command bar, Cmd+Q, Arc shortcuts not also firing a menu item.
4. Default browser from the installed app; `.html` via `open-file`.
5. Gatekeeper first launch of the DMG from the release; README instructions accurate.
6. Visual polish on macOS still to look at: dark-appearance spaces, hover/active states, split view, Little Window, Peek's look (card size, buttons, backdrop).

Screen captures: with Screen Recording and Accessibility granted to the Claude Code `claude.app` (not Claude.app), `screencapture -R` and System Events work. YARC's own look is designed here, not copied: don't measure or trace another app's UI, binary or files beyond what a user's own data export needs (the importers).

Updates (`src/main/update/updater.ts`): Windows auto-updates with electron-updater (NSIS, unsigned is fine) from the GitHub release's `latest.yml`, and only installs an installer whose Ed25519 `.sig` matches `UPDATE_PUBLIC_KEY` (`verifyInstaller` in `src/main/update/update-signature.ts`; electron-updater installs on quit only once that check passes). macOS updates itself without a Developer ID (Squirrel.Mac refuses ad-hoc signatures, so not electron-updater): `src/main/update/mac-update.ts` polls `releases/latest`, downloads the arch's `-mac.zip` with Node's fetch (no quarantine flag), checks its Ed25519 `.sig` against `UPDATE_PUBLIC_KEY` (`src/main/update/update-signature.ts`; CI signs with the `MAC_UPDATE_SIGNING_KEY` secret), unzips into the profile's `Update/` folder and swaps the bundle at quit. Tested on macOS 26.5 from a local feed (2026-11-02): no Keychain or App Management prompt; camera/microphone grants survive updates only with the self-signed certificate (`docs/electron-notes.md` sections 8 and 9). If the app's folder isn't writable it falls back to opening the DMG. Linux is notify-only. A downloaded update is quiet, like Arc's: a *Restart to Update* pill in the sidebar and install on quit; the relaunch card (an overlay listing every version since the running one) only opens by itself after 7 days without a restart, then at most daily, or after 1 day when the release's `release.json` names a different Electron than `process.versions.electron` (`src/main/update/update-escalation.ts`; the wait is kept in `state.json` as `waitingUpdate`). Packaged builds only; not yet tried end to end against a real published release.

Releases: v0.1.2 is the latest manual release; from then on `main` releases automatically, once a day (see Commands). Dependabot patch/minor bumps auto-merge; only Electron's are released at once (labeled `release:now`), the others are labeled `release:skip` and ship with the next real change (`.github/workflows/dependabot-automerge.yml`).
